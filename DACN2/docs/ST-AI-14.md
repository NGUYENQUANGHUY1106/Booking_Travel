# ST-AI-14 — Hotel embeddings

## Source and visibility contract

| Source | Public gate | Change detection | Indexed chunk | Consumer |
| --- | --- | --- | --- | --- |
| Hotel name, description, check-in/out | Latest `HotelSubmission.status=APPROVED` and live `Hotel.status=APPROVED`, `isVisible`, `deletedAt IS NULL` | Approval enqueue + five-minute reconciliation | `HOTEL_OVERVIEW`, submission version/hash | Internal `HotelEmbeddingService.retrieve` |
| Hotel amenities | Same approved snapshot and live gate | Same | `AMENITIES` | Same |
| Cancellation policy and house rules | Same approved snapshot and live gate | Same | `HOTEL_POLICY` | Same |

The extractor never serializes Hotel/User/Room entities. Contact, address, owner verification, private media, prices, inventory, booking and payment data are absent from its allowlist. Public free text strips HTML, URLs and common email/phone/ID patterns. This is defense in depth, not a guarantee that arbitrary prose has no personal information; moderation still owns that decision. Hotel text is untrusted source data, never an instruction. Oversized policies are omitted instead of quoting an incomplete condition. No FAQ table exists. Room/review content is deliberately excluded until its public moderation/provenance contract is verified. Approved snapshot remains the content source while editable drafts exist. Structured refund rules edited outside the moderation snapshot are not embedded.

## Pipeline

`approve/restore/hide/suspend → post-commit enqueue → BullMQ worker → latest approved snapshot → bounded embedding request → row-locked visibility/version check → pgvector upsert`. A five-minute reconciliation scans Hotels by cursor to recover missed enqueue events, and removes chunks for revoked Hotels. Retrieval requires a use case (`PUBLIC_SEARCH` or `HOTEL_SUPPORT`); support requires a hotel ID supplied by trusted server context. It joins live Hotel, ready index state and the latest approved submission in the same SQL statement. It filters model, dimensions, chunk schema and optional trusted hotel scope. It returns source IDs, version, excerpt and citation; it never returns raw vectors. Callers must re-check public status immediately before constructing any answer/card. Search/Availability/Pricing remain the authority for prices, inventory and bookability.

`AI_EMBEDDING_ENABLED=false` leaves the worker off and `retrieve` returns `INSUFFICIENT_DATA`; normal booking/search is unaffected. No AI chat or Search consumer exists in the current `AiModule`, so this change exposes an internal service contract for AI-01/02/12 and adds no public debug route or mock UI.

## Configuration and operations

Set `AI_EMBEDDING_PROVIDER` to a stable identifier and change it whenever the embedding endpoint/model family changes. Retrieval refuses vectors generated by another provider even when the model name is reused.

Set `AI_EMBEDDING_ENABLED=true`, `AI_EMBEDDING_API_URL`, `AI_EMBEDDING_API_KEY`, `AI_EMBEDDING_MODEL` and `REDIS_URL` in the local environment. The endpoint must implement the OpenAI-compatible embeddings response with **1536 dimensions**; changing dimension requires a new migration and backfill. Never commit credentials. Run `npm.cmd run prisma:generate`, `npm.cmd run prisma:migrate`, then start API. BullMQ runs inside the API process with two workers, five bounded attempts, exponential backoff and a failed-job retention window. `HotelEmbeddingQueueService.diagnostics()` reports queue lag, stale/revoked chunks and missing hotel counts; `HotelEmbeddingService.counters` reports local attempts, successes, failures, retrieval, empty and fallback counts. Failed jobs and state `FAILED/errorCode` can be inspected without reading raw hotel text. Logs use hotel ID and error code only.

Run `npm.cmd run hotel-embeddings:backfill --workspace @booking-travel/api -- --dry-run` to inspect candidates or `npm.cmd run hotel-embeddings:backfill --workspace @booking-travel/api -- --cursor=<last-id>` to resume. The command processes 100 hotels at a time and prints the next cursor. A completed job is idempotent by source hash and approved version. If Redis is unavailable, enqueue is skipped; reconciliation retries later. A provider error never rolls back hotel approval. Do not expose this command through a public API.

Rollback: disable `AI_EMBEDDING_ENABLED`, redeploy the preceding API, and retain embedding tables/vector extension for forward repair. Do not drop pgvector or the Docker volume. Re-enable and rerun backfill after fixing the provider or schema. The model is an exact cosine scan initially; no ANN index was added without cardinality/recall measurements. The 0.65 distance cutoff is an application relevance guard, not a measured SLA.
