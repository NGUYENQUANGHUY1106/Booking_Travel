# TK-07 – Seed ba role và dữ liệu demo có thể tái lập

## Task này dùng để làm gì?

Mỗi thành viên có PostgreSQL riêng nên dữ liệu trong pgAdmin không đi theo Git. TK-07 cung cấp một lệnh tạo cùng bộ dữ liệu mẫu trên mọi máy để có thể đăng nhập và kiểm thử ngay mà không phải nhập tay User, Hotel Owner, Admin, khách sạn, phòng, booking hay tin nhắn.

Seed chỉ dành cho môi trường local/demo. Lệnh dùng `upsert` với email, slug, code và ID cố định: chạy lại sẽ khôi phục dữ liệu chuẩn và không nhân bản bản ghi. Seed không xóa tài khoản hoặc dữ liệu khác do lập trình viên tự tạo.

## Dữ liệu chính

| Role | Email | Mật khẩu |
| --- | --- | --- |
| User | `traveler@bookingtravel.vn` | `traveler123` |
| Hotel Owner | `owner@bookingtravel.vn` | `owner123` |
| Admin | `admin@bookingtravel.vn` | `admin123` |

Ngoài ba tài khoản chính, seed giữ thêm Owner B, Traveler B và Admin giới hạn để kiểm tra truy cập chéo/RBAC.

Dữ liệu liên kết gồm:

- 3 khách sạn, 4 hạng phòng và ảnh local của hai khách sạn công khai.
- 2 booking đã xác nhận.
- Một block phòng ngày 20–21/12/2026 và một override còn 3 phòng ngày 24/12/2026.
- Một hội thoại Blue Horizon có 3 tin nhắn, trong đó một tin User gửi chưa được Owner đọc.

## Cài đặt hoặc nạp lại dữ liệu

Chạy tại thư mục `DACN2`:

```powershell
npm.cmd install
npm.cmd run prisma:generate
npm.cmd run prisma:migrate
npm.cmd run prisma:seed
```

Máy mới có thể dùng một lệnh thay cho ba lệnh Prisma cuối:

```powershell
npm.cmd run db:setup
```

## Kiểm tra tự động

Lệnh sau cố ý chạy seed hai lần rồi kiểm tra mật khẩu, ba role, ownership, khách sạn, phòng, booking, inventory và chat. Nếu không có dữ liệu trùng/sai quan hệ, lệnh kết thúc với exit code 0:

```powershell
npm.cmd run prisma:seed:test
```

Chỉ kiểm tra dữ liệu hiện có, không chạy seed lại:

```powershell
npm.cmd run prisma:seed:verify
```

Kết quả đúng:

```text
Seed hợp lệ: 3 roles đăng nhập được; ownership, hotel, rooms, booking, inventory và chat đều đúng.
```

## Kiểm tra bằng pgAdmin 4

Mở database `booking_travel` → Query Tool và chạy:

```sql
SELECT id, email, role, status, "isActive"
FROM public."User"
WHERE email IN (
  'traveler@bookingtravel.vn',
  'owner@bookingtravel.vn',
  'admin@bookingtravel.vn'
)
ORDER BY role;

SELECT h.name, h.status, u.email AS owner, COUNT(r.id) AS rooms
FROM public."Hotel" h
JOIN public."User" u ON u.id = h."ownerId"
LEFT JOIN public."Room" r ON r."hotelId" = h.id
WHERE h.slug = 'blue-horizon-my-khe-hotel'
GROUP BY h.id, u.email;

SELECT c.id, h.name, COUNT(m.id) AS messages,
       COUNT(m.id) FILTER (WHERE m."readAt" IS NULL) AS unread
FROM public."Conversation" c
JOIN public."Hotel" h ON h.id = c."hotelId"
LEFT JOIN public."Message" m ON m."conversationId" = c.id
WHERE h.slug = 'blue-horizon-my-khe-hotel'
GROUP BY c.id, h.name;
```

Kết quả mong đợi: ba tài khoản có ba role khác nhau và đều `ACTIVE`; Blue Horizon có hai phòng; hội thoại có ba tin nhắn và một tin chưa đọc.

## Kiểm tra trên ứng dụng

1. Chạy API: `npm.cmd run dev:api`.
2. Chạy Expo ở terminal khác: `npm.cmd run dev:mobile`.
3. Đăng nhập User để xem khách sạn/booking và gửi tin nhắn.
4. Đăng xuất, đăng nhập Hotel Owner để xem phòng, lịch phòng và tin chưa đọc.
5. Đăng xuất, đăng nhập Admin để xem/quản lý khách sạn.

Nếu lệnh verify đạt nhưng app không tải dữ liệu, kiểm tra `EXPO_PUBLIC_API_BASE_URL`: điện thoại thật không thể dùng `localhost` của máy tính.
